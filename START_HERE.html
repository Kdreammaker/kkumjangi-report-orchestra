  • GitHub는 시스템을 받는 통로이고, 실제 자료와 문서 산출물은 이 로컬 드라이브에 남습니다.

새 프로젝트 시작 문구에만 자동 반영됩니다. AI는 주제와 목적을 보고 프로젝트명, 폴더명, 첫 산출물명을 제안합니다. 프로젝트 폴더는 승인된 이름을 안전한 파일명으로 줄인 YYMMDD_이름앞부분 형식으로 만들어지고, 이미 열린 프로젝트에서 이어서 작업할 때는 프로젝트 대시보드와 tasks/current_task.md를 기준으로 AI가 찾습니다.

0. 바로 시작

처음에는 아래 흐름만 보면 됩니다. 검수 결과에 따라 고도화와 재검수를 반복하고, 충분히 안정되면 조립과 공유 준비로 넘어갑니다.

새 프로젝트주제와 목적을 넣고 세팅안을 승인합니다.
초안 작성프로젝트 작업표를 기준으로 필요한 단계부터 진행합니다.

설치 직후에는 같은 환경 점검을 다시 요청할 필요가 없습니다. 바로 새 프로젝트나 문서 작업을 요청하세요.

1. 새 프로젝트 시작

새 주제로 작업할 때는 이 문구부터 사용합니다. AI는 파일을 만들기 전에 세팅안을 먼저 제안하고 확인을 받아야 합니다.

복사용 문구

새 프로젝트를 시작해 주세요.
주제: [주제]
한 줄 목적: [한 줄 설명]

AGENTS.md에서 새 프로젝트 규칙만 확인한 뒤, 먼저 세팅안을 제안하고 제 승인을 받아 주세요.
승인 전에는 파일 생성, 자료 인테이크, 문서 작성은 하지 마세요.

새 프로젝트 착수처럼 작업표가 아직 없는 경우에만 AGENTS.md를 먼저 봅니다. 프로젝트가 만들어진 뒤에는 tasks/current_task.md가 다음 작업을 안내합니다.

2. 문서 작성 요청

프로젝트가 만들어진 뒤에는 이 문구로 보고서, 교안, 제안서, 핸드아웃 같은 산출물 초안을 작성합니다. 초안은 최종본이 아니라 검수와 교차검증을 위한 내부 검토본입니다.

1

목차 먼저

바로 본문을 쓰지 않고 목적, 독자, 상세 목차, 주요 골조를 먼저 잡습니다.

2

장별 작성

대목차별 HTML 조각을 만들고, 내용을 충분히 보강한 뒤 합칩니다.

3

표·그래프

표만 늘리지 않고 차트, 타임라인, 다이어그램이 더 맞는지 확인합니다.

4

초안 보고

작성 뒤에는 완료 선언이 아니라 검수 대상 초안으로 보고합니다.

복사용 문구

현재 프로젝트의 문서 작성 작업을 진행해 주세요.
프로젝트의 tasks/current_task.md를 먼저 읽고, active 단계가 요구하는 범위까지 진행해 주세요.
승인이나 확인이 필요한 지점에서는 멈춰서 알려 주세요.

3. 중단 후 이어가기

작업이 중간에 멈췄거나 다른 AI가 이어받을 때는 새 프로젝트 정보를 다시 길게 붙이지 말고, 현재 프로젝트의 작업표를 먼저 읽게 합니다.

복사용 문구

현재 프로젝트 작업을 이어서 진행해 주세요.
프로젝트의 tasks/current_task.md를 먼저 읽고, active 단계가 요구하는 파일과 규칙만 확인해 주세요.
직전 작업에서 실패하거나 차단된 검증이 있으면 완료라고 말하지 말고, 차단 사유와 다음 조치부터 정리한 뒤 진행해 주세요.

이 문구는 컨텍스트 초과, 새 스레드 전환, 다른 AI로 이어받기 때 사용합니다. 문서 작성 자체는 작업표의 active 단계가 허용하는 범위까지만 이어갑니다.

4. 자료와 레퍼런스 정리

자료는 프로젝트의 자료 폴더에 넣고 AI에게 정리를 요청합니다. 웹 자료는 접속 가능한 공식 링크와 접근일이 남아야 합니다.

웹 레퍼런스는 파일 다운로드를 시도하지 않고, 정확한 링크와 접근일을 남기는 방식으로 정리합니다.

복사용 문구

현재 프로젝트의 자료를 정리해 주세요.
프로젝트의 tasks/current_task.md를 먼저 읽고, 자료 폴더의 새 파일과 URL을 참고자료 목록에 등록해 주세요.
외부 레퍼런스 파일 다운로드는 시도하지 말고, 정확한 공식 링크와 접근일을 남겨 주세요.
파일 자체가 필요하면 사용자에게 요청할 항목으로 분리해 주세요.

문서 검수 때는 참고자료가 “있는지”보다 “접속 가능한 링크, 원문 여부, 인용 검증 상태가 분리되어 있는지”가 중요합니다.

5. 검수와 교차검증

검수는 같은 AI나 같은 스레드에서도 먼저 수행할 수 있는 절차와 완성도 점검입니다. 교차검증은 가능하면 다른 AI나 새 스레드에서 독립 리뷰어 관점으로 핵심 주장과 결론을 흔들어 보는 작업입니다.

복사용 문구: 검수

현재 프로젝트의 문서를 검수만 해 주세요.
프로젝트의 tasks/current_task.md를 먼저 읽고, 파일은 수정하지 말고 문제점과 보완 필요 사항을 먼저 알려 주세요.
고도화가 필요하면 바로 수정하지 말고, 후속 요청에 사용할 보완 목록으로 정리해 주세요.

검수는 파일을 고치기 전 문제 목록을 받는 용도입니다. 같은 AI가 셀프 체크로 먼저 수행해도 되지만, 통과 선언은 근거와 남은 위험을 분리해야 합니다.

복사용 문구: 교차검증

현재 프로젝트 문서의 핵심 주장과 결론을 교차검증해 주세요.
프로젝트의 tasks/current_task.md로 산출물 위치와 상태만 확인한 뒤, 파일은 수정하지 말고 독립 리뷰어 관점으로 봐 주세요.
빠진 근거, 반례, 과장된 표현, 추가 확인이 필요한 주장, 결론이 바뀔 수 있는 조건을 찾아 주세요.
URL 출처는 정확한 공식 링크, source locator, 접근일, 사용 수준이 남아 있는지 확인하고, 파일 자체가 필요하면 사용자 요청 자료로 분리해 주세요.
후속 고도화에서 반영할 항목과, 조치해도 해결하기 어려운 한계를 구분해 주세요.

교차검증은 작성자와 다른 AI나 새 스레드에서 수행할수록 좋습니다. 목적은 점수 확인이 아니라 결론을 바꿀 수 있는 누락과 반례를 찾는 것입니다.

선택 문구: 축약형·상세형·위임형

필요할 때만 아래 문장을 덧붙입니다. 기본값은 표준 분량과 단계별 확인형입니다.

  • 축약형으로 작성해 주세요. 핵심 구조는 유지하되 표준 분량의 30~60% 수준으로 줄여 주세요.
  • 상세형으로 작성해 주세요. 근거와 예시가 충분한 범위에서 표준 분량의 180~250% 수준까지 확장해 주세요.
  • 위임형으로 진행해 주세요. 목표 지점까지 가능한 범위에서 진행하고, 완료 후 가정한 내용·확인이 필요한 이슈·실패한 검증·남은 리스크를 브리핑해 주세요.

6. 문서 고도화 요청

고도화는 초안을 바로 다시 쓰는 요청이 아니라, 검수나 교차검증에서 나온 보완 목록을 반영하는 단계입니다. 보완이 안정된 뒤에만 조립과 공유 준비로 넘어갑니다.

복사용 문구

현재 프로젝트의 문서를 고도화해 주세요.
프로젝트의 tasks/current_task.md를 먼저 읽고, 이전 검수/교차검증 결과를 반영해 주세요.
관련 원본을 수정하고, 바뀐 점과 남은 리스크를 알려 주세요.

목차 수는 고정하지 않습니다. 주제 범위와 독자 의사결정에 맞게 대목차·중목차·소목차를 설계해야 합니다. 소목차는 짧은 메모가 아니라 독자가 판단할 수 있는 분석 단위여야 합니다.

7. 후속 산출물 만들기

이미 만든 산출물을 바탕으로 다른 문서를 만들 수 있습니다. 순서는 고정되어 있지 않습니다. 보고서에서 교안으로 갈 수도 있고, 교안에서 요약 보고서로 갈 수도 있으며, 제안서에서 핸드아웃으로 갈 수도 있습니다.

복사용 문구

현재 프로젝트의 산출물을 바탕으로 후속 문서를 만들고 싶습니다.
먼저 원본 프로젝트의 tasks/current_task.md와 최신 산출물 버전/경로를 확인해 주세요.
새 후속 프로젝트를 만들지, 같은 프로젝트 안의 새 산출물로 둘지 제안해 주세요.
새 산출물의 목적, 예상 독자, 출력 형태를 합리적으로 추정해 기본 PRD안을 만들고, 꼭 필요한 확인 질문만 해 주세요.
원본에서 재사용할 범위와 새로 검증해야 할 범위를 구분하고, 작성 전 세팅안을 먼저 제안해 주세요.

후속 산출물도 새 초안이면 버전이 새로 남아야 합니다. 이전 산출물의 출처와 결론은 참고 맥락이지, 새 문서에서 자동 검증 완료가 아닙니다.

8. 공유 패키지

공유 패키지는 문서 파일만 보내는 것이 아니라, 검토에 필요한 근거 묶음을 함께 정리하는 단계입니다. 외부 업로드는 별도 승인 후 진행합니다.

  • 포함: 문서 산출물, 참고자료 목록, 출처 링크 목록, 주장 대장, 표·그래프 데이터
  • 제외: 민감 원본, 불필요한 작업 로그, 검증되지 않은 임시 파일

복사용 문구

현재 프로젝트의 공유 패키지를 준비해 주세요.
프로젝트의 tasks/current_task.md를 먼저 읽고, 외부 업로드 없이 로컬 공유 패키지를 준비해 주세요.
문서와 함께 검토에 필요한 참고자료 목록, 출처 링크, 주장 근거, 표·그래프 데이터의 포함/제외 항목을 보고해 주세요.

9. 재점검이 필요할 때

설치 직후에는 보통 필요하지 않습니다. 폴더를 옮겼거나, 시간이 오래 지났거나, 다른 PC에서 다시 시작할 때만 사용하세요.

복사용 문구

이 작업공간을 재점검해 주세요.
AGENTS.md에서 작업공간 점검 규칙만 확인한 뒤 필요한 범위만 점검해 주세요.
가능하면 현재 로컬 VERSION.json/커밋과 origin/main의 최신 상태를 비교해 주세요.
origin이 private 저장소이고 시스템 코어에 로컬 변경이나 충돌 위험이 없으면 git pull --ff-only로 최신화해 주세요.
ZIP 설치, public 원격, 로컬 변경, 충돌 가능성, 판단이 애매한 경우에는 업데이트하지 말고 상태만 보고해 주세요.
설치 직후 기본 검증과 중복된다면 그 점을 먼저 말하고, 환경/구조 검증과 프로젝트 산출물 품질 검증을 구분해서 보고해 주세요.
활성 프로젝트 산출물을 따로 검수하지 않았다면 문서 내용, 출처 진위, 법률 해석, 인용 정확성을 검증했다고 말하지 마세요.
