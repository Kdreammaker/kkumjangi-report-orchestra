# Contributing

Thank you for helping improve Report Integrity Orchestrator.

## Before Opening an Issue

- Do not attach private reports, source files, internal company materials, or local absolute paths.
- If a bug involves a report project, create a small synthetic example instead of sharing real material.
- Separate environment/setup problems from report-content quality problems.

## Useful Bug Report Details

- System version from `VERSION.json`.
- Operating system, AI app, and model used when the issue happened.
- Python version when the issue involves install/runtime behavior.
- Whether the issue happened during install, project setup, reference intake, dashboard use, report writing, validation, or packaging.
- The exact validator result when available.

## Pull Requests

- Keep changes scoped.
- Update `CHANGELOG.md`, `README.md`, and `VERSION.json` for behavior changes.
- Run local validators before asking for review.
- Do not include user workspaces, runtime caches, parsed private files, or generated project outputs.
